# iOS 저장소 역할과 다음 작업

공통 기준: [architecture](system/architecture.md), [plan](system/plan.md), [policies](system/policies.md).
현재 SwiftUI 뼈대를 넘어선 기능 구현은 아직 없다. 아래는 정책 확정 후 수행할 계획이다.

| 작업 | 책임 | 완료 시 관찰할 것 |
|---|---|---|
| APP-00 | P01·P03·P04·P07·P09 적용 | 최소 iOS 버전, 설정/캐시, 지역/시간대, 화면 범위 확정 |
| APP-01A | backend 계약 기반 API client | 정상/오류/빈 값/미정 decode, 계약 버전 참조 |
| APP-01B | 달력·카드·상세 | 같은 입력의 이벤트 집합 일치, 날짜 정밀도·출처·상태 표시 |
| APP-01C | 필터·기기 저장 | 계약대로 조건 전달, 종료·재실행 후 설정 재조회 |
| APP-01D | 누락/오래된 캐시/장애 상태 | 정책에 맞는 사용자 표시, 최신 수집 시각 구분 |
| APP-02 | 자체 단위·UI 검사와 독립 handoff | app/backend 조합·계약·필수 검사·미실행 항목 기록 |

정규화·콘텐츠 식별·중복 병합·외부 제공처 비밀은 backend 책임이다.
필요한 API 변경은 backend 계약 변경안으로 협의하고 앱 쪽 모델에만 새 필드를 가정하지 않는다.

문제 해결·ADR 원본은 이 저장소에 남기고 통합 학습 해설은 `verifier/docs/learning`에 연결한다.
기존 학습·bootstrap 기록은 당시 사실을 보존한다. 과거의 앱 전용 검사를 통합 검사로 다시 표기하지 않는다.

## 월간 캘린더·통일한 찜 동작 후속

극장 영화 개봉일·EPL 경기 포함, 신규 기본 영화·OTT/설정에서 게임·EPL 추가, 작품·일정 찜 모두 지원을 반영한다.
공통 설계의 화면/찜 후속 항목과 app/docs/design/calendar-first.md, backend ADR-006에 따라 소유 범위를 구현/독립 검토한다.

OTT는 최초 공개일만 제공한다. 회차별 공개/완결은 제외하며 시즌별 최초 공개 포함은 후속 추천안 수락으로 확정했다. 메인은 선택한 캘린더 중심안이다.

로그인 전 공개 일정 조회, Google 로그인 후 찜·설정 저장, V1 알림 제외를 로컬 구현 계약/검사 초안에 반영한다.

API 소비 메모와 계약 commit/digest는 docs/api에 둔다. 실제 네트워크/DTO 구현 전 계약 검토를 진행한다.
