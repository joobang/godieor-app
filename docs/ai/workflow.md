# AI를 활용하는 작업 단위

목표는 많은 에이전트를 쓰는 것이 아니라, 작은 변경마다 근거를 남기고 다른 문맥에서 오류를 찾는 것이다.

새 개발 대화는 [현재 상태](../system/status.md)와 [계정·모델 인계 절차](../system/handoff.md)부터 읽는다.
시작할 때 [작업 카드](task-template.md)에 담당·기준 커밋·범위를 기록하고, 끝날 때 중단 위치·다음 행동·실행 결과를 남긴다.
웹 전달 파일은 `python3 scripts/export-context.py`로 생성한다. 구현 맥락 공유와 독립 리뷰 입력은 구분한다.

## 역할

| 역할 | 입력 | 쓰기 범위 | 산출물 |
|---|---|---|---|
| 사람/요구사항 소유자 | 제품 의도·기준 초안·검토 | 승인 기록 | acceptance 버전 승인, 출시/수정 결정 |
| 설계·구현 AI | 개발 요구사항, 승인된 기준, API 계약, 이슈 | 해당 앱 또는 backend 코드·자체 테스트·설계 문서 | 변경, 실행 결과, 검증 handoff |
| 독립 리뷰 AI | 고정 SHA snapshot, 승인 기준, 독립 리뷰 지침 | 별도 결과 디렉터리 | finding·severity·근거·재현·미확정 항목 |
| test runner | 고정 snapshot의 빌드용 사본, 검증 레포의 검사 명령 | 빌드/결과 공간 | 명령·종료 코드·로그·시간 |
| verdict engine | 검사·리뷰·정책 상태 | JSON/Markdown report | 결정적 PASS/FAIL/REVIEW_REQUIRED/ERROR |

독립 리뷰에는 구현자의 대화·자기평가를 넘기지 않는다. requirement ID, base/head SHA,
앱·backend의 고정 버전 조합, 계약·마이그레이션 digest, 공식 외부 근거와 변경 사실만 넘긴다.
같은 모델이어도 별도 컨텍스트로 시작한다.
모델을 바꾸는 것은 선택 사항이며 독립성이나 정확성을 자동 보장하지 않는다.

## 한 번의 변경 흐름

1. 사람 승인 기준을 버전/해시로 고정한다. 개발 AI는 기준을 제안할 수 있고 승인할 수는 없다.
2. 개발 AI가 requirement ID, 범위, 실패 가설, 실행할 검사를 1개 작업 카드에 적는다.
3. 구현·자체 검사를 수행한다. 작은 변경을 검토 가능한 단위로 만든다.
4. 사용자 요청 범위에서 commit하고 앱·backend의 정확한 SHA와 계약·마이그레이션을 검증 대상으로 넘긴다.
5. 구현 예정인 검증 저장소 CLI가 두 SHA를 snapshot으로 고정한다. 원본과 빌드 사본을 나눈다.
6. 별도 컨텍스트 리뷰와 실행 검사를 진행한다. 필수 검사 누락·환경 오류는 PASS 금지.
7. 프로그램이 evidence를 집계한다. AI 리뷰는 최종 PASS를 선언하지 않는다.
8. 사람이 승인/수정/재검증한다. 새 SHA에는 기존 PASS를 재사용하지 않는다.

현재 bootstrap에는 요구사항 초안·리뷰 프롬프트·판정 엔진과 자기 검사가 있다.
자동 snapshot/실행 runner/AI 어댑터와 OS 격리는 아직 구현하지 않았다.
현재 evidence v1은 app만 처리하며, backend 조합 식별은 evidence v2로 확장할 예정이다.
이 상태에서 제품 검증 완료 또는 전체 V1 완성이라고 표현하지 않는다.

## 개발 작업 카드 템플릿

```text
작업 ID / requirement ID:
사용자에게 달라지는 동작:
변경 범위:
실패 가설 / 경계 조건:
자체 검사 명령과 실제 결과:
app base/head SHA:
backend base/head SHA:
API 계약·마이그레이션 digest:
외부 검증 대상 / 남은 불확실성:
```

## 결정·학습 기록

사용자 요청에 따라 [통합 학습 카탈로그](https://github.com/joobang/godieor-verifier/tree/dev/docs/learning)를 초기 작업에 포함한다.
중요한 선택·문제 해결 원본은 각 저장소 ADR/작업 기록에 남기고, verifier/docs/learning에서
기술 원리·대안·면접/블로그 해설을 LEARN 기록으로 연결한다.
검사 결과는 verifier 원본을 링크한다. 반복 실패가 있으면 독립 규칙 검토에 넘긴다.
매 작업은 [작업 카드](task-template.md)에 학습 기록 ID 또는 해당 없음의 이유를 남긴다.
AI 초안과 검증된 사실, 사용자가 직접 설명한 내용을 구분한다. 외부 게시를 자동 실행하지 않는다.
별도 지식 플랫폼이나 대시보드는 V1 범위에 넣지 않는다.
