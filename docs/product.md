## 아직 확정하지 않은 정책

- backend framework=NestJS, DB=PostgreSQL, ORM=Prisma, TypeORM 제외는 2026-11-09 사용자 확정.
  최종 실행 위치는 본인 iPhone 앱 + 클라우드 API/DB, Mac verifier로 확정했다. 첫 개발 목표는 로컬 실행이다.
  현재 SwiftUI·iOS 17 이상 구성을 유지하며 정확한 backend/DB 버전·클라우드 제공자·설치/배포 수단은 미정이다.
- 로그인: 계정 기반 + Google 연동을 V1 방향으로 사용자 선택했다.
  로그인 없는 기기 전용 계정 제안은 대체한다. 개인 설정·찜의 계정 저장/복원은 확정했고, 세션·동기화 충돌·계정 삭제 상세는 추가 설계한다.
- 대상 OTT 4곳은 확정했다. 실제 작품/회차·지역별 공개일 근거를 확보하고 미지원/누락 범위를 명시한다.
  국가별 플랫폼 가용성만으로 공개 날짜를 추정하지 않는다.
- 업데이트 주기는 하루 1회로 확정했다. 실패 시 마지막 데이터·성공 시각, 연기/취소 상태 표시를 확정했다. 실제 실행 시각·재시도·캐시 기한은 추가 설계한다.
- 찜 대상 단위(작품/개별 일정/둘 다)는 확인 중이다. 지역·기기·계정 귀속·가입 허용 범위는 후속 답변을 반영했다.
- 수익화·App Store 공개 시점·AI 모델/예산·실행 격리 방식은 미정.

## 일정 데이터 설계 원칙

콘텐츠 ID와 공개 이벤트 ID를 분리한다. 이벤트에는 콘텐츠 참조, release kind, 지역,
플랫폼 목록, 회차, 출처 이벤트 키, 상태, 원본 수정 시각, 수집 시각을 둔다.
중복 기준은 제목이 아니다. 출처의 안정적인 이벤트 ID를 우선 사용하고,
다른 출처의 병합은 지역·회차·공개 방식·시간 정밀도를 확인한 뒤 수행한다.
일정이 변경돼도 기존 이벤트 ID와 수정 이력을 유지한다.

시간 값은 다음 세 형태를 구분한다.

- `instant`: offset이 있는 실제 시각을 UTC로 저장하고 사용자 시간대로 표시.
- `date_only`: 해당 지역의 달력 날짜를 그대로 보존. UTC 자정으로 변환하지 않음.
- `unknown`: 달력 날짜 없음. 연도·월·분기만 아는 경우 원본 정밀도를 별도로 보존하고 날짜를 만들지 않음.

플랫폼 가용성은 공개 이벤트의 근거와 별개다. ‘한국 Netflix에서 볼 수 있음’은
‘이 날짜에 한국 Netflix 공개’의 증거가 아니다.
