## 아직 확정하지 않은 정책

- SwiftUI 및 iOS 최소 버전, 서버·DB 제공자: 기술 제안 문서 참조.
- 로그인/기기간 동기화: V1에서는 로그인 없이 기기 설정만 저장하는 방안을 제안.
- OTT 범위: 한국에서 공개가 확인된 드라마·회차만 제공하는 방안을 제안.
  모든 OTT를 빠짐없이 지원하거나, 국가별 플랫폼 정보만으로 공개일을 추정하지 않는다.
- 업데이트 주기, 캐시 허용 시간, 연기/취소 표시 방식은 데이터 검증 후 결정.
- 수익화·App Store 공개 시점·AI 모델/예산·실행 격리 방식은 미정.

## 일정 데이터 설계 원칙

콘텐츠 ID와 공개 이벤트 ID를 분리한다. 이벤트에는 콘텐츠 참조, release kind, 지역,
플랫폼 목록, 회차, 출처 이벤트 키, 상태, 원본 수정 시각, 수집 시각을 둔다.
중복 기준은 제목이 아니다. 출처의 안정적인 이벤트 ID를 우선 사용하고,
다른 출처의 병합은 지역·회차·공개 방식·시간 정밀도를 확인한 뒤 수행한다.
일정이 변경돼도 기존 이벤트 ID와 수정 이력을 유지한다.

시간 값은 다음 세 형태를 구분한다.

- `instant`: offset이 있는 실제 시각을 UTC로 저장하고 사용자 시간대로 표시.
- `date_only`: 해당 지역의 달력 날짜를 그대로 보존. UTC 자정으로 변환하지 않음.
- `unknown`: 달력 날짜 없음. 연도·월·분기만 아는 경우 원본 정밀도를 별도로 보존하고 날짜를 만들지 않음.

플랫폼 가용성은 공개 이벤트의 근거와 별개다. ‘한국 Netflix에서 볼 수 있음’은
‘이 날짜에 한국 Netflix 공개’의 증거가 아니다.
