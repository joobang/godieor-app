# ADR-003 · 계정 세션과 비동기 작업의 소유권

2026-11-13 구현 결정. 원본 작업 APP-AUTH-13, 통합 해설 LEARN-0020. 실사용자 장애 보고가 아닌 개발 중 합성 재현이다.

기존 sessionGeneration/token 검사는 다른 계정의 응답 반영을 막지만, 같은 계정의 연속 설정 저장 응답과 공용 busy의 defer까지 보호하지 못했다. 실제 AccountState를 실행한 15개 합성 시나리오에서 네 결함을 재현했다. 로그아웃 직후 busy가 남고, 이전 작업 defer가 새 계정 작업을 해제하고, 늦은 v2 응답이 이미 확인한 v3 저장을 덮고, 새 계정의 최초 조회 실패 때 이전 설정·찜이 남았다.

busy는 UUID를 가진 현재 작업만 해제한다. 로그아웃/401은 소유권을 무효화하고 즉시 busy를 해제한다. 설정 저장은 시작한 mutation revision과 세션을 응답·오류·오류 후 재조회 완료 시점에 대조한다. 새 로그인 세션 발급 시 이전 계정의 설정·찜·동기화 시각·pending을 비운 다음 재조회한다. 요청 취소에만 의존하지 않는다. 이미 서버에서 완료된 쓰기를 취소가 되돌린다고 가정할 수 없기 때문이다.

초기 복원 중 네트워크 실패는 세션을 보존한다. 계정 화면의 재시도 및 앱 active 복귀에서 다시 조회하고, 401만 로컬 세션을 지운다. 계정 로그인 성공과 설정·찜 동기화 성공은 별도로 표시한다.

HTTP/세션 저장/Google 인증 결과를 주입 가능한 경계로 만들었다. iOS 기본 동작은 기존 URLSession·ThisDeviceOnly Keychain·GoogleAuthorization이다. macOS 자체검사는 실제 AccountState와 합성 의존성을 연결한다. UI 상호작용·실 Keychain·OAuth·기기간 통합·독립 검증의 대체물이 아니다. 계약·백엔드·migration은 변경하지 않는다.
